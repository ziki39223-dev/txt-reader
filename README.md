# TxtBar —— 把 Windows 任务栏的位置变成逐行阅读器

在系统任务栏那一整条上显示一条**同位置、同尺寸**的阅读条：
左边四个按钮（菜单 / 上一页 / 下一页 / 切换谁在前），中间按**固定字数**一行一行显示 txt，右边是进度状态。
默认直接盖住系统任务栏，看起来就像任务栏本身在帮你读书。
**关掉再打开会接着上次那一行继续**；支持查找，找到哪一行就从哪一行开始读。

同时带一个**源文本清洗工具**：网上下的 txt 往往同一章印两遍、满篇水印、句子被硬换行切断，
洗一遍再读，"下一页"才是老老实实往下走。

打开方式：双击 `TxtBar.exe`（已编译好，不需要装任何东西）。

## 一、当前版本做了什么

| 要求 | 实现 | 验证 |
| --- | --- | --- |
| 和 Windows 状态栏一样 | 运行时读出系统任务栏真实矩形（本机 1920×72 @ (0,1128)），窗口摆成同一位置同一尺寸；底色跟着系统浅/深色主题 | 实机量真实窗口：`1506x72 @(0,1128)`，与任务栏**纵向逐像素重合**，右端让出托盘 |
| 能直接代替状态栏 | 窗口是置顶 + 工具窗口 + **不抢焦点**，点按钮不会把正在用的软件顶掉。正文主动让出右下托盘区 | 实机确认 exStyle `0x8010088`（我的条在前）/ `0x8010080`（系统任务栏在前）；托盘/时钟/显示桌面照样能点 |
| **上一页 / 下一页放菜单外面** | 主页面四个按钮：菜单 · 上一页 · 下一页 · 切换。点一下走一行，`↑ ← PageUp`、滚轮向上同效 | 自检投递真实点击：第 1 行 →「下一页」走一行 →「上一页」回到原处；实机连点 6 次，每次前进 1 行 |
| 一行固定字数 | 默认每行 48 字（可 ±2 调，或直接选 18~64）。字号默认自适应 = 正文区宽 ÷ 每行字数 | 自检真测量：40 字实宽 1040px ≤ 正文区 1068px |
| 每次打开接着上次 | 每翻一行就写 `%LOCALAPPDATA%\TxtBar\settings.json`；同时在书旁边写一份 `<文件名>.txtbar.json` | 自检模拟重启：存第 138 行 → 新建窗体 → 恢复第 138 行 |
| **一开机就看得见** | 上次如果是停在「系统任务栏在前」退出，条会沉到任务栏后面，下次启动什么都看不见 —— 很容易以为程序没起来。所以「谁在前」**不跨启动记忆**：读到的行号、每行字数、字号照旧恢复，只有层叠每次都从「我的条在前」开始 | 自检：把 `CoverTaskbar` 故意存成 0 → 启动 → `status.json` 里立刻是 `true`，且点击条的位置最上层窗口就是我们的条 |
| **不出现空行** | 切行时直接跳过空行（连「只由空格/制表符组成」的行也跳过，包括段落尾巴被切出来的纯空白片段） | 含 441 个空行的 txt 实机连翻 120 屏，空行出现 **0** 次 |
| **正文不能拖动** | 彻底删掉拖动逻辑，空白处按下不做任何事，鼠标回到普通指针 | 自检：在正文区拖 380px，横向位置仍是 0 |
| **查找并从命中处开始** | 基于**全文索引**，关键词跨切行边界也能命中，找到后直接定位到那一行并高亮 | 实机键盘输入「第 300 行」回车：从第 0 行跳到显示行 598 |
| **切换入口有两个：条上一个 + 最右边常驻一个** | ① 主页面第 4 个按钮（⇄），紧挨「下一页」右边 ② 任务栏最右端「显示桌面」那块常驻一个小方块，一直看得见。两处点哪个都行，**切换只改谁盖住谁，不改位置** | 自检：第 4 个按钮与「下一页」同一行同尺寸、间距 3px；常驻方块 51×72 @(1869,1128) 贴住任务栏右端、高度一致；两个入口各点一次都生效。实机 PostMessage 交替点：`false→true→false→true` 三次全生效，常驻方块位置始终 `1869,1128,51x72`，条始终 `1506x72 @(0,1128)` |
| **方向键一次只走一行** | 低级键盘钩子对「按下」「抬起」都会回调，早先没筛消息类型，敲一下 ↓ 会被当成两次 → 一次跳两行。现在只认「按下」，按住不放靠系统的按键重复连续翻 | 实机：敲一下 ↓ / PageDown 都是 `12 → 13`（前进 1 行），敲一下 ↑ 是 `13 → 12`；连续 12 次按下前进 13 行 |
| **搜了 305 读完不会再绕回 305** | 源文件里同一章印两遍（章号 305 / 530 各一份，正文一字不差）。清洗时把重复的整块和整章删掉，同一个章号只留一条 | 实机脚本复现「搜 305 → 一路往下读」：原始版又遇到一次含 305 的行，且 305 章正文首句在后面**再次出现**；清洗版命中 **1** 处、正文首句后面**0** 次重现 |
| **源码清洗 + 两个文件夹** | ①「书库\原始\<书名>\」放你下的 txt（一本书一个子文件夹，可以多个）②「书库\已清洗\<书名>\」放洗好的同名 txt，直接读 | 见第四节：一本 495 万字的书，洗掉 47% 的重复与水印，512 章编号连续 |

## 二、操作方式

**主页面只有四个按钮：菜单 · 上一页 · 下一页 · 切换谁在前**（都在最左边，紧挨着排）

上一页 / 下一页点一下就翻一行。其余全部收进菜单（点最左的菜单按钮，或在条上任意处按右键）：

| 分组 | 里面有什么 |
| --- | --- |
| 打开与查找 | 打开 txt · 继续读上次那本 · 最近读过的书（最多 8 本）· 查找 · 读剪贴板 |
| **源文本清洗（书库）** | **清洗源文本…** · **打开「已清洗」文件夹** |
| 阅读控制 | 回到第一行 · 跳到末行 · 自动翻行开关 · 自动翻行速度（1/2/3/5/10 秒一行） |
| 显示设置 | 每行字数（18/24/28/32/36/40/48/56/64 字，或 ±2）· 字号（自适应 + 13~29px，或 ±）· 不显示空行 · 把所有空行从正文里清掉 · 外观（跟随系统/浅色/深色）· 正文横向归位 |
| 任务栏与退出 | 我的条显示在系统任务栏前面（谁在前）· 最右侧那个切换入口摆在哪 · 让路 3 秒 · 重新贴齐任务栏位置 · 全局接管方向键 · 退出 |

**切换「谁在前面」——两个入口，点哪个都行**

| 入口 | 位置 | 特点 |
| --- | --- | --- |
| 条上的按钮 | 主页面第 4 个，紧挨「下一页」右边 | 跟着条走；我的条在前时图标是**强调色**常亮 |
| 常驻小方块 | 任务栏**最右端**（平时「显示桌面」那一块） | 一直置顶、一直看得见，条被系统任务栏盖住时它也在 |

点一下就切换：

- **我的条在前**：阅读条压在系统任务栏上，右下角的托盘、时钟、输入法照样露在外面能用
- **系统任务栏在前**：阅读条原地退到任务栏后面（位置尺寸不动，只是被任务栏盖住）

鼠标停在任一个入口上，条上都会提示「点这里会发生什么」。两种模式**位置完全一样**，切换只是换谁在上面，
所以不会出现「切完跑到任务栏上面去」。`F7` 同效，菜单里「我的条显示在系统任务栏前面」那一项也同效。

> 常驻小方块占的正是「显示桌面」按钮那一块。它默认放在最右端，菜单里可以改成「退到我的条最右边」。
> 直接按 `Win` + `D` 一样能显示桌面，我们不会拦它。

**键盘**（只在桌面 / 任务栏上是前台时生效，不会影响你在别的软件里打字）

| 按键 | 作用 |
| --- | --- |
| `↑` `↓` `←` `→` · `PageUp` · `PageDown` | 翻行（鼠标滚轮同效） |
| `Ctrl` + 滚轮 | 调字号 |
| `/` | 打开查找（`回车`下一个、`Shift+回车`上一个、`Esc` 收起） |
| `空格` | 自动翻行 开/关 |
| `Home` / `End` | 第一行 / 末行 |
| `=` / `-` | 每行字数 +2 / −2 |
| `F7` | 切换「谁在前面」 |
| `F8` | 字号自适应 开/关 |
| `F9` | 让路 3 秒 |
| `菜单键` | 弹出完整菜单 |

## 三、几个设计取舍

**查找为什么用全文索引**
按显示行找的话，关键词被切行切断就搜不到了。所以把全文拼成一条长字符串、记下每个字符属于哪条显示行；
查找在这条长串上进行，命中后反查回显示行。跨行词也能找到，且定位一次到位。

**切换为什么留两个入口**
两个入口解决的是两件不同的事：

- **条上的按钮**：手已经在条上了，翻页顺手切一下，不用把鼠标甩到屏幕最右端
- **最右边的常驻方块**：切到「系统任务栏在前」时，整条阅读条都被任务栏盖住，条上的按钮自然也看不见了。
  这时只有任务栏最右端那个始终置顶的小方块还能点，点它就能把条叫回来 —— 它是个「回来」的把手

阅读条只铺到「托盘左边」为止（本机 1506px），右下角那一块完整留给系统，所以常驻方块不会跟正文挤。
它自己的位置跟着任务栏走（任务栏挪了、分辨率变了都自动跟上），切换「谁在前」时它不会动。

**字号自适应**
默认开着。你调「每行字数」，字号跟着重算，始终让那一行正好铺满正文区。

**编码**：自动识别。有 BOM 按 BOM；否则严格试 UTF-8，失败退回 GB18030（兼容 GBK/GB2312）。
> 这里有个坑踩过：UTF-8 探测如果直接截前 256KB 丢给严格解码，很可能正好切在一个汉字的中间，
> 会被误判成 GB18030 而整篇读成乱码。现在改成增量解码、尾部残缺字符挂起，不再误判。

**开机自启**：把 `TxtBar.exe` 的快捷方式放进
`%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup` 即可。

**关于安全软件误报**
这个程序没有联网代码、不读写别的进程内存、不写注册表、不申请管理员权限，也没有加壳。
但它的行为天生容易被盯上：装全局键盘/鼠标钩子、开一个伪装成任务栏的置顶窗口、枚举 `Shell_TrayWnd`、
定时读剪贴板。这些叠在一起，安全软件容易判成「可疑」。

已经做的收敛（降低误报概率）：

- **补了完整版本信息**：`FileVersion 1.1.0.0`、`ProductName TxtBar`、`FileDescription`、`CompanyName`、`Copyright`
  都编进 exe 了。之前是「无公司 / 无版本 / 无描述」的三无文件，这类文件的误报率明显更高
- **没有加壳、没有网络、没有自启、没有提权**：申请级别是 `asInvoker`

还能进一步做的（需要你点头）：剪贴板监视默认关掉、钩子改成按需安装（只在条是前台时才装）、做代码签名。

## 四、源文本清洗（书库）

### 目录怎么放

```
书库\
├─ 原始\                    ← 你下好的 txt 放这里
│   └─ 示例书\               ← 一本书一个文件夹（章数多的一般是多个 txt）
│       ├─ 示例书_1-500章.txt
│       └─ 示例书_501-790章.txt
└─ 已清洗\                  ← 洗好的结果自动放这里
    └─ 示例书\
        ├─ 示例书_1-500章.txt   ← 同名，一对一，不合并
        └─ 示例书_501-790章.txt
```

一个 txt 洗成一个**同名**的 txt，结构不变、没有合并 —— 你读哪一个都行，章号跨文件接着数。

> 仓库只保留这两个空文件夹，不带任何小说 txt（版权内容不进库）。书自己放进去即可。

### 怎么用

- 双击 `TxtClean.exe` → 扫整个书库，洗完弹一张报告（带「打开已清洗文件夹」按钮）
- 或者：阅读条菜单 →「源文本清洗（书库）」→「清洗源文本…」
- 命令行：`TxtClean.exe --quiet`（报告打到控制台，便于自动化）

### 它到底洗了什么

| 病症 | 说明 | 处理 |
| --- | --- | --- |
| **同一段内容印两遍** | 这本书实测重复内容占 **47%**，翻着翻着就绕回刚才读过的段落 | 连续 ≥12 段、≥400 字与前面完全相同 → 认定整块重复，把后面那份删掉 |
| **一句话被硬换行切断** | 源文件按约 50 字折行，阅读器再按每行字数切一次，就碎成一条 2 个字的尾巴（"所以下一行其实是它的后半截。"） | 上一段结尾不是句末标点、且下一段不带缩进 → 接回成一条完整的话 |
| **水印** | `(本章完)`、`来源：xx`、`网址：http://…`、「记住我们网」、【最快小说站…】、分割线 | 整行命中即删（822 行） |
| **章号乱** | 中文数字与阿拉伯数字混排，还大量倒退（第九十章 后面跟第84章）；每章还印两行标题（中文一行、阿拉伯一行） | 章号**原样保留**，取的是这一章正文前面最后一个标题。不顺排、也不整体重排 —— 重排成 1,2,3… 会让「搜 305 章」直接搜不到 |
| **只有标题没正文的空章** | 重复打印出来的标题 | 丢掉（638 个） |
| **紧挨着重复的行** | 同一行印了两遍，粘起来会变成两个半句硬拼在一起 | 相邻完全相同的行直接删 |

### 实机实测（约 500 万字的示例合集）

```
清洗完成：1 本成功
合计 467 章，4953595 字 → 2615167 字（砍掉 47% 的重复和水印）
每个 txt 洗成同名的 txt，结构不变、没有合并。

■ 示例书
   示例书_1-500章.txt · GB18030 · 41451 行
       水印 517 行 · 310 章 · 2568474 字 → 1422384 字
   示例书_501-790章.txt · GB18030 · 39432 行
       水印 345 行 · 157 章 · 2385121 字 → 1192783 字
   合计：重复行 18 条 · 整块重复 393 处 · 重复章节 8 章 · 空标题 675 个
```

另外做了两条**硬不变量**校验（不是"看着像对"，而是逐条比对）：

- 清洗结果里的 **41567 条正文段落，逐条都能在原文里原样找到** —— 0 条是凭空拼出来的
- 清洗结果里**没有任何两章的正文一字不差** —— 读到重复内容的情况为 0

**清洗前后，翻页节奏的差别**（统计"点一次下一页，原文往前走了几行"）：

| | 显示行数 | 点一次下一页的前进量 |
| --- | --- | --- |
| 清洗前 | 79490 | 原地不动 38039 次，**一次跳过 3 行以上 41447 次** |
| 清洗后 | 41440 | 原地不动 18954 次，前进 1 行 22485 次，**跳 3 行以上 0 次** |

清洗后：512 章编号**完全连续**，没有一会倒退一会重复的章号。

## 五、自检

```bat
build.bat
```

用系统自带 csc 编译（主程序 + 清洗工具）→ 跑 **70 项自检**。当前结果：

```
环境：dpi=144 scale=1.50 taskbar=1920x72 @ (0,1128) tray=366 theme=light aligned=left
=== 结果：70 项通过 / 0 项失败 ===
```

不少检查不是"算出来"而是"真做出来"的：

- 真创建窗口句柄量矩形 —— 必须和系统任务栏一模一样
- 真渲染成位图逐块统计墨迹 —— 按钮区 / 正文区 / 状态区都必须真有内容
- **真的投递鼠标点击给按钮** —— 点「下一页」必须往下走一行，点「上一页」必须原路退回
- 真的在正文区拖一把 —— 横向位置必须纹丝不动
- 真的走一遍查找（往后找 / 往前找 / 末尾绕回 / 找不到）
- 空行：默认不出现；关掉开关能恢复显示；整篇都是空行时不会变成空白屏
- 条上的切换按钮：必须紧挨在「下一页」右边（同一行、同尺寸、间距 ≤12px、不越出条外）；图标真画出来了（不是空心方块）；
  点它能来回切换；鼠标移上有提示；配色随「谁在前」变（强调色 29‰ ↔ 0‰）
- 最右端的常驻入口：必须贴在任务栏最右端、高度与任务栏一致、鼠标移上有提示；点它也能来回切换（两个入口并存）
- 版本信息：公司 / 产品 / 描述 / 版本号四项都得有（三无 exe 是安全软件误报的高发区）
- 切换「谁在前」：两种模式都切一遍，窗口矩形必须一个字都不变，且绝不会浮到任务栏上方
- **键盘**：直接喂（消息, 虚拟键）给钩子判断核心 —— 「按下」走一步、「抬起」不再触发
- **清洗**：没有空行 / 没有水印残留 / 断句接回 / 标题身份在去重前就定好（重复内容不会吃掉章节边界）/
  章号原样保留（搜「305 章」还能搜到）/ 整块重复只留一份 / 多个 txt 各洗各的 / 中文章号与阿拉伯章号都认得

命令行开关：

```bat
TxtBar.exe --selftest           自检（报告写 %LOCALAPPDATA%\TxtBar\selftest.log）
TxtBar.exe --dpi                打印 DPI 感知状态与任务栏几何
TxtBar.exe <某个.txt>           直接用这本书启动
TxtBar.exe --global             启动就全局接管按键（在任何程序上按 Esc 都能退出）
TxtClean.exe [书库目录]          清洗源文本
TxtClean.exe --quiet            清洗并把报告打到控制台
```
